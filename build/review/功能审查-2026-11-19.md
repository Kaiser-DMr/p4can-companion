# P4 管家 App 功能审查报告

- 日期：2026-11-19
- 版本：3.30 / build 51
- 范围：iOS 主 App（含 Mac Catalyst）、Widget / Live Activity、App Intents、核心网络层，以及 App ↔ 固件 / mock 的接口契约
- 方法：五个只读审查员并行分域审查，全部结论要求 `文件:行号` 证据；契约部分运行 `build/tools/check_api_contract.py` 并对照 `web_api.h` 与 `build/mock/mock_p4can.py`
- 结果：**127 条原始发现**（跨模块重复已在本文合并标注）。分模块明细见 `build/review/details/`

优先级定义：**P0** 给出错误结论或核心流程不可用；**P1** 核心流程缺陷、可致误操作；**P2** 一致性与体验；**P3** 改进建议。

---

## 一页结论

1. **OTA 在真机上从未真正成功过**：设备重启后 `/api/ota/status` 返回 `ok:false`，被客户端当成业务错误抛出，确认阶段空转 120 s 后判「未完成」。（P0）
2. **切换设备地址不清状态**：旧车的车型、挡位、扭矩、CAN、趋势会以新地址的名义继续显示，且新设备缓存永不加载。（P0）
3. **总线故障会被显示成健康**：`BUS-OFF` 因 `ready` 位被判在线，出现「绿点 + BUS-OFF + 3/3 在线」。（P1）
4. **「在线」不等于「数据新鲜」**：任一慢端点成功就把整页标为已同步，核心指标可能已冻结数小时。（P1）
5. **灯光能力只建模了三分之一**：固件支持 COUNT / DURATION / MANUAL 三种模式，App 只认 COUNT；设备处于其它模式时界面数值全错且无法纠正。（P1）
6. **多处「点了没反应」有同一类根因**：命令忙时静默丢弃、轮询覆盖用户输入、能力位缺省当作「支持」。（P1）

- 状态页卡片齐全：车型头卡、四个 KPI、电池、快捷开关、CAN 总线、扭矩趋势、车型能力、蓝牙、OTA、设备、实时活动；首次连不上时有空态与连接引导入口。

### 1.3 P2 / P3（10 + 9 条，摘）
离线判定抖动（每次重试先「连接中」约 8 s）、离线原因直接上屏 HTTP 文案、状态页 OTA 失败提示因字段类型读错永不出现、OTA 期间首页仍显示高频同步、整页 2–4 Hz 全量重建、SOC 未校验 0–1/0–100、三路 CAN 角色按固定顺序绑定导致拓扑切换错标、快捷开关把「未知」当「支持」且离线可点、同屏四五套在线/未知/缓存表达、网络日志 300 条只覆盖 15–60 s、LiveData 默认展开项不匹配、缓存单槽不按设备隔离、iOS 无桌面 Widget。

### 1.4 缺失 / 重复 / 逻辑不合理
- **缺失**：没有数据新鲜度模型（per-endpoint 时间戳）；没有前后台切换处理；没有设备重启识别（uptime 骤降不触发复位）；没有离线退避；实时活动无「过期」表达。
- **重复**：全局轮询 + LiveData 3 s 轮询；缓存判定两套（`hasRenderableData` 与 `isShowingCachedData`）；总线色调三份（`P4Tone` / `P4BusState.color` / Dashboard）。
- **逻辑不合理**：请求前先置 `.connecting`，把「重试」说成「正在连接」，离线态被自己覆盖；`addTrendSample` 被 profile/features 刷新额外触发，时间轴密度不均。

## 2. 功能与灯光（Features / 详情页 / 两路灯效）

### 2.1 功能现状
- 24 个模块按灯光 / 驾驶辅助 / 车身与舒适 / 高级与兼容分组；支持搜索、长按置顶（上限 6）、深链。
- 控件形态：toggle、endpointToggle、数值滑杆、成对滑杆、命令按钮、分段 Picker；写入走统一 `command` 通道。
- 前大灯页：按住开关 → 状态 → 触发（CommitButton 四态）→ 运行状态 → 参数（两把刻度尺 + 触发入口 + 保存/撤销）。
- 后雾灯页：30 秒圆环 + 开始/停止 + 运行状态。
- `check_api_contract.py` 通过：路径与参数名全部匹配固件，未发现「必然 400」的控件。

### 2.2 P0 / P1

| 级别 | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| P1 | 固件有三种爆闪模式（COUNT / DURATION / MANUAL），App 只建模 COUNT | `HeadlightStrobeView.swift:68-71,482-487` vs `fw/headlight_strobe.h:210-220` | 设备处于 DURATION/MANUAL 时，次数/间隔/总时长全部失真，且保存只发 4 个参数无法纠正 | 读回 `mode`，按模式切换参数区；非 COUNT 模式显示只读说明 + 「切回次数模式」 |
| P1 | `AppEnvironment.command` 忙时静默 `return`，调用方仍按「已提交」继续 | `AppEnvironment.swift:672`、`FeatureDetailView.swift:595-602` | 开关「点了没反应」、后续提示误判成功 | 返回明确结果（accepted/rejected），调用方据此回滚并提示「设备忙」 |
| P1 | 详情页 1.2 s 轮询覆盖本地输入 | `FeatureDetailView.swift:266-281,397-417` | Picker 回弹、成对滑杆被中断，用户以为改不了 | 所有可编辑控件加编辑锁（现有仅单个 number 有），提交期间暂停回写 |

### 2.3 P2 / P3（9 + 11 条，摘）
前大灯间隔上限 500 ms 而固件接受 50–1000（保存即静默改写）、两页失败文案各自映射且与固件错误码脱钩、ISA/DMS 无失败态与重试、搜索不覆盖实验室、DEBUG 深链让同一模块出现双入口、`FeatureDetailView` 中 headlight/rearFog 的两段入口不可达、`pairNumber` 无编辑锁、写入无「进行中」禁用。

### 2.4 缺失 / 重复 / 逻辑不合理
- **缺失**：`durationMs / stopMode / maxRunMs / mode` 未建模；`holdDelayMs` 只读不可改；后雾灯 `pulses / frameAgeMs / templateHex` 未展示。
- **重复**：灯光分组同时存在「直达页」与「通用详情页」两条路径（后者实际不可达）。
- **逻辑不合理**：`triggerSource=1` 的提示只看本地值，不看 `dirty`，与设备侧状态短暂不一致；`saveDisabled` 含 `active`，但固件其实允许运行中改 `intervalMs`，属双边设计冲突。

### 5.1 现状与基线

### 5.2 P0 / P1

| **P0** | `interpret` 把「状态里的 `ok:false`」当业务错误 | `P4APIClient.swift:424-429` | OTA 状态卡片读不到数据、上传确认永远失败（见 3.2） | 先看 HTTP 状态，再决定是否把 `ok:false` 当错误；OTA 状态走宽容读取 |

### 5.3 缺失 / 重复 / 逻辑不合理
- **缺失**：无测试 target / CI（`build/mock/CoreSmokeTest.swift` 是手工 `@main`，不入工程）；无请求取消（OTA 上传 900 s 超时会一直锁住状态）；无退避策略。
- **重复**：三套 URLError→文案映射；两套 Card、三套状态徽章、两套命令通道；两套语言判定（`L10n.resolved` 与 `P4IntentLanguage`，当前结论一致但会漂移）。
- **逻辑不合理**：`interpret` 先判 `error` 键后判 HTTP 状态；注释写「每 4 拍」实际每 2 秒；`P4FirmwareUploader` 完成后不释放 buffer。

## 6. 跨模块系统性问题

1. **状态双源与轮询泛滥**：全局轮询 + 6 个页面各自轮询 + 诊断/无线/数据浏览自建定时器，既造成状态不同步，也在抢单线程固件的连接。
2. **没有「数据新鲜度」模型**：只有设备在线/离线，无法表达「设备在线但这条数据是 10 分钟前的」，这是多条 P1 的共同根源。
3. **错误语义三层不统一**：`URLError` → 可操作中文；`P4APIError` → 固件英文原文；HTTP 非 2xx → 「请求失败：HTTP 409」。同一故障在不同页面三套措辞。
4. **能力位缺省当作「支持」**：`supportKey` 缺失、`featuresStatus == nil`、能力位拼错时，一律按可操作处理，最终以 409 收场。
5. **危险操作与导航可见性耦合在功能开关上**：关掉蓝牙/LAB 就失去重开入口；这是「功能和它自己的开关打架」。
