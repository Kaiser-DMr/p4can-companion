# 固件代码审查（2026-11-19）

审查对象：`build/firmware-build/P4-CAN-Universal-v3.29.3/` 的灯光补丁
基线：`build/firmware-build/stock/P4-CAN-Universal-v3.29.3/`（原版）
审查方式：独立 subagent 只读审查，按 `requesting-code-review` 模板输出；本轮随后修复并重编 fix4。

## 一、结论

- 传输层门控（epoch、总线新鲜度、维护模式、被动抓包）设计正确，复用了上游屏障而不是另造一套。
- 但审查发现 **6 个 Critical**，其中 5 个已在本轮修复；1 个（0x273 counter/checksum）证据不足，暂不改代码，需台架确认。
- 修复后 `arduino-cli` 编译通过，产物 `P4CAN-v3.29.3-fix4-20261119.ino.bin`（1,402,608 B）。
- 未经台架/实车回归：按住 30 s、按住点停止、断一路总线、epoch 抖动四个场景需要现场验证。

## 三、Important 与处理

已修：

- **I1 配置半生效**：改为先解析到 `HeadlightStrobeConfig next`，全部校验通过后一次性提交。
- **I2 运行中一律 409**：收窄为只拦截 count/trigger/duration/stopMode/maxRun/holdDelay；放行 `intervalMs` 与 `holdEnabled`，运行中关开关会真正停止并恢复。
- **I3 epoch 取到 0 误判**：`canTxEpochSnapshot()` 返回 0 时视为“本拍未知”，不触发 `CAN_EPOCH_CHANGED`；首次拿到非 0 时补记基线。
- **I7 `loadPrefs` 失败锁存**：`begin()` 成功后才置 `headlightStrobePrefsLoaded`；失败则下次重试，不会把默认值 clamp 成“1 次 + 50 ms”。
- **I9 后雾灯模板过期不恢复**：`NO_FRAME` 停止时模板通常已过期；现在允许用 10 s 内的旧模板补发一次原状态，避免后雾灯留在常亮。
- **GET 副作用**：GET 现在严格只读，即使带 query 也不改 RAM/NVS。

未修（记录在案）：

- **I4 web 侧无锁读多字段**：建议后续提供 `*Snapshot()` 一次进锁拷贝。
- **I5 0x249 模板无时间戳**：只保证“曾经收到”，不保证“正在收”；加 TTL 可能误伤事件型车型，需实车确认后再定。
- **I6 每次保存 8 次 NVS commit**：可改为只写变化键并检查返回值；当前仅在用户保存时发生，优先级较低。
- **I8 `trigger=1`（S3XY）无消费者**：配置后手动触发必 409；应补动作映射或在配置层拒绝。
- **I10 事件型 0x249 松手无法检测**：需实车波形确认松手是否回帧。
- **I11 连续 5 次发送失败无退避**：约 5 ms 窗口就终止整轮，建议按 20 ms 退避。
- **I12 `begin()` 锁外判 active、取模板白耗 counter**：并发触发时统计可能被覆盖。
- **I13 后雾灯在 CAN 任务停摆时 30 s 上限不生效**：`observe()` 路径仍会回帧。

## 四、审查给出的优点

- 停止顺序正确：先清 active，再恢复，最后释放 0x249 独占。
- `sendStalkFrame*` 单一出口加守卫，覆盖转向/ALC/one-shot 全部路径。
- 复用上游 epoch 屏障/新鲜度/维护模式门控，总线 off、被动抓包、维护模式在发送时刻被挡。
- GET 无 NVS 写入的根因修复彻底。
- 按住检测读 `realRaw249`（整车帧），避开自激反馈。
- 后雾灯模板记录 bus，回复同总线。
- 内嵌 HTML 生成链路确定性，解压后与 `dashboard_source.html` 逐字节一致。
- 时间比较全部 wrap-safe；新增路径无动态内存。

## 六、待现场验证

1. 按住拨杆超过安全上限：应只停一次，不自动重启；松开再按住才重新起爆。
2. 按住期间点「停止」：应立即停并恢复，之后不再自动起爆。
3. 后雾灯：开始后断开 0x273（拔总线/断电），灯不应停在常亮。
4. epoch 抖动/一路总线 off：爆闪应停止，恢复帧在 2 s 内重试；失败时 stats 出现 `RESTORE_FAILED`。
5. Web UI：两个灯光面板的开关、滑杆、开始/停止、返回键都可用。
