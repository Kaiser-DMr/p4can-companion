# 3.35.3 免重启补丁 → 3.35.8 对比与验证

日期：2026-11-25

## 1. 结论

**3.35.8 已经内置了这套「缓存 0x331 + 上电补发」的免重启逻辑，不需要再移植。**

提供的 `P4CAN-V3.35.3-刷机包(4).zip` 里的修复来自上游分支
`06066060606060/P4can-universal-unlock` → `tlssc-fix`，提交：

- `5b841783` fix(TLSSC Restore): cache and replay patched 0x331 to avoid MCU reboot on every power cycle
- `5f8bf7d5` Merge pull request #15 from baicyber/fix/eap-anti-restart

新增文件 `eap_anti_restart.h`（180 行），接入点只有 5 行：

| 文件 | 改动 |
|---|---|
| `P4-CAN-Universal-v3.35.3.ino` | include `eap_anti_restart.h` |
| `can_runtime.h` | CAN B / extra 两条 0x331 路径调用 `eapNrObserve331()`；服务循环调用 `eapNrTick()` |
| `service_settings.h` | include；`eapNrStatsAppend()` 并入 service-mode 统计 |
| `web_api.h` | 统计输出带上 eap 字段 |

而 3.35.8 的 OTA 包里存在同一套状态机的全部状态字段和 NVS 键，说明作者在
3.35.5 之后已经把这份修复合并进主线，并在 3.35.7/3.35.8 继续改过字段名。

## 2. 二进制证据

对比对象：

- 修改版 3.35.3：`P4CAN-C6-OTA-V3.35.3.bin`（SHA-256 `67172520…F6C337`）
- 官方 3.35.8：`P4-CAN-Universal-v3.35.8.OTA.REV3.X.bin`

| 特征 | 修改版 3.35.3 | 官方 3.35.8 | 3.35.6 |
|---|---|---|---|
| NVS 键 `eapFrame` | ✅ | ✅ | ❌ |
| `cacheValid` | ✅ | ✅ | ❌ |
| `cacheLen` | ❌（用 cacheHex 长度） | ✅ | ❌ |
| `cacheHex` | ✅ | ✅ | ❌ |
| `persisted` | ❌ | ✅ | ❌ |
| `replayOk / replayFail / replayBusy / replaySkip` | ✅ | ✅ | ❌ |
| `burst` | ✅ | ✅ | ❌ |
| `lastErr / lastErrName` | 部分 | ✅ | ❌ |
| `windowExpired` | ❌（用 `windowLeftMs`） | ✅ | ❌ |
| 独立 `/api/eap-norestart/*` | ✅ | ❌（并入 `service-mode/stats`） | ❌ |

3.35.8 里这些字段紧跟在 `canEnter` 之后，属于
`/api/service-mode/stats` 的 JSON；`eapFrame` 与 `tlHwy/tlNoa/blkA/...`
同处一组 NVS 键。字段组合与 `eapNrStatsAppend()` 一致，只是把
`epoch` 换成了 `windowExpired`、新增 `persisted/cacheLen`。

## 3. 两版行为差异

| 项目 | 修改版 3.35.3 | 3.35.8 内置 |
|---|---|---|
| 开关 | 独立 `/api/eap-norestart/update?enabled=` | 跟随「恢复红绿灯 / 停车标志辅助（TLSSC）」 |
| 状态接口 | `/api/eap-norestart/stats` | `/api/service-mode/stats` 扁平字段 |
| 缓存 | 最近一帧补丁后的 0x331，写 NVS | 同一 NVS 键 `eapFrame` |
| 补发窗口 | 60 s / 10 Hz / 最多 600 帧 | 存在 `windowExpired`，窗口参数需实测 |
| 让位条件 | 车端 0x331 新鲜 2 s / TX 屏障忙 | `replayBusy/replaySkip` 计数一致 |
| 前置条件 | `prereq`（恢复开关 + 非封禁） | `chinaRestore` 开关即前置 |

核心逻辑相同：**上电后先把缓存帧补发出去，让车机在启动读取 DAS 配置时看到
SELF_DRIVING，而不是等车自己发 0x331 后再改（那时已经锁存）。**

## 4. 为什么没有改固件

- 3.35.8 的源码未公开：上游仓库只有 `3.35.3` 标签，`main` 和 `tlssc-fix`
  分支仍停在 3.35.3（`P4-CAN-Universal-v3.35.3.ino`）。
- 3.35.8 已经包含同一套修复，再做源码移植没有目标文件可改。
- 直接改 OTA 二进制（追加代码段、重算镜像校验）风险远高于收益，且无法保证
  与 3.35.8 内部的 CAN 路由/屏障地址一致，可能直接刷坏。

如果实测 3.35.8 的 `service-mode/stats` 里**没有** `cacheValid/replayOk`
这些字段，说明手上不是这份带修复的构建；把该 bin 发来做二进制特征比对，
或等作者公开 3.35.8 源码后再做源码级补丁。

## 6. 验证步骤

### 6.1 前置

1. 刷入 `P4-CAN-Universal-v3.35.8.OTA.REV3.X.bin`。
2. App / 网页进入 Service Mode，打开「恢复红绿灯 / 停车标志辅助（TLSSC）」。
3. 车辆上电，让总线出现至少一帧车端 `0x331`（通常解锁/上高压后即有）。
4. 确认 `cacheValid=true`、`cacheHex` 以 `1B` 开头、`persisted=true`。

### 6.2 自动检查

```bash
./build/firmware-build/verify-3358-antirestart.sh 192.168.4.1
```

脚本会输出缓存、补发计数、窗口状态，并给出结论：

- `OK`：缓存有效且已补发成功
- `WAIT`：窗口还在进行，等 60 s 再查
- `NO-CACHE`：从未捕获到补丁后的 0x331（TLSSC 未开或车没发帧）
- `TX-BLOCKED`：有缓存但补发一直失败，检查 CAN 总线/屏障
- `NO-FIELD`：该固件没有内置补发状态字段

### 6.3 实车重启验证

1. 保持 TLSSC 恢复开启，整车断电（P4-CAN 也断电）。
2. 重新上电，**不要**手动重启车机。
3. 上电后 10 秒内查询一次：

   ```bash
   curl -s http://192.168.4.1/api/service-mode/stats
   ```

   预期：`burst` / `replayOk` 比上次熄火前增加，`cacheValid=true`。
4. 等 60 秒后再查：`windowExpired=true`，`replayOk` 不再增长。
5. 看车机：红绿灯/停车标志辅助应直接可用，不需要再重启 MCU。
6. 重复 2–5 两到三次；每次都应自动恢复。

### 6.4 失败判读

| 现象 | 含义 | 处理 |
|---|---|---|
| `cacheValid=false` | 没抓到补丁后的 0x331 | 确认 TLSSC 恢复已开；车端确实有 0x331；等一帧后再断电 |
| `persisted=false` | NVS 写入失败 | 检查 flash/NVS 是否满，重置设置后重试 |
| `replayOk=0`，`replayFail` 增长 | 补发被 TX 屏障/总线拒绝 | 看 `lastErrName`：`TX-busy` 让位、`gate-closed` 检查挡位/总线、`send-failed` 检查收发器 |
| `windowExpired=true` 且 `burst=0` | 窗口内没有发出任何帧 | 缓存为空或 CAN 未 ready，查 `debug` 日志 |
| 字段不存在 | 固件不是带修复的构建 | 换用带 `eapFrame` 的 3.35.8 包 |

## 7. 限制

- 3.35.8 的窗口参数（60 s / 10 Hz / 600 帧）是从 3.35.3 补丁推断的，二进制里
  只能确认 `windowExpired` 与 `burst` 存在，具体数值需实测确认。
- 若车机在 P4-CAN 上线之前就完成 DAS 配置读取，任何软件补发都来不及；这种
  情况仍需一次人工重启。补发只能把「每次上电都要重启」降为「极少数情况」。
