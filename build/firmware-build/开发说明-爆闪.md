## 2. 原固件审查（改动前的状态）

### 2.1 3CAN 结构

| 总线 | 引脚（X179 线束） | 用途 |
|---|---|---|
| CHASSIS (CH) | GPIO2 TX / GPIO3 RX | 车辆 13/14 |
| BODY / VEH | GPIO4 TX / GPIO5 RX | 车辆 9/10 |
| PARTY (PT) | GPIO26 TX / GPIO27 RX | 车辆 2/3 |

- 三路 TWAI 驱动，`canTask` 单循环处理 RX → 各业务 tick → `canTwaiHandleAlerts()` → 恢复监督；
- `pin_config.h`、TWAI 初始化、滤波器、任务优先级、看门狗喂狗点 **均未改动**。

### 2.2 0x249（SCCM 拨杆）注入现状

固件本来就会「克隆最近一帧真实 0x249 → 改字段 → 重算 CRC → 发回」：

| 入口 | 函数 | 用途 |
|---|---|---|
| 自动转向灯 | `sendStalkFrameCanB()`（Model YL）/ `sendStalkFrameCanA()`（其它车型） | 轻拨一下自动打三下 |
| ALC / one-shot | 同上，带 `directUser` | 变道辅助的一次性闪烁 |

两条发送路径都带 `canTxEpochSnapshot()`（总线恢复即作废）和 TX trace 标记，**这是必须复用的安全机制**。

### 2.3 其它约束

- 必须先抓到过真实 0x249（`stalkFrameSnapshot`），否则不造帧；
- 车型分 `TURN_SIGNAL_STALK` / `TURN_SIGNAL_STALKLESS`（Highland 无拨杆 → 不可用）；
- 所有注入共用 0x249，谁在发谁独占，必须互斥。

## 4. 配置接口（触发 / 关闭 / 时长都不写死）

### 4.1 参数

| 参数 | 范围 | 默认 | 含义 |
|---|---|---|---|
| `count` | 1–30 | 10 | COUNT 模式下的闪烁次数（一次 on/off 算一次） |
| `intervalMs` | 50–1000 | 200 | 半周期（on 或 off 各占这么久） |
| `trigger` | 0 / 1 | 0 | 触发方式：0 = App/网页，1 = S3XY |
| `durationMs` | 0 或 100–30000 | 0 | **总时长**；>0 时覆盖 `count`（DURATION 模式），0 = 用 count 算 |
| `stopMode` | 0 / 1 / 2 | 0 | 关闭方式：0 = 到时自动停；1 = 只能手动停（持续频闪）；2 = 到时或手动都可 |
| `maxRunMs` | 500–60000 | 30000 | 安全上限，任何模式到点强制停 + 恢复 |

三种模式（`mode` 字段回显）：

| mode | 触发条件 | 结束条件 |
|---|---|---|
| `COUNT` | `durationMs=0, stopMode≠1` | `count × 2 × intervalMs` 后自动停 |
| `DURATION` | `durationMs>0, stopMode≠1` | `durationMs` 后自动停 |
| `MANUAL` | `stopMode=1` | 只由 `/stop` 停止；`maxRunMs` 兜底 |

### 4.2 接口

```bash
# 读配置+状态
curl -s http://192.168.4.1/api/headlight-strobe/config

# 改成：每秒 2 次、共 3 秒、到时自动停
curl -X POST "http://192.168.4.1/api/headlight-strobe/config?count=6&intervalMs=250&durationMs=3000&stopMode=0"

# 改成：持续频闪，只能手动停，最长 20 秒
curl -X POST "http://192.168.4.1/api/headlight-strobe/config?intervalMs=120&durationMs=0&stopMode=1&maxRunMs=20000"

# 触发 / 停止 / 查状态
curl -X POST http://192.168.4.1/api/headlight-strobe/trigger
curl -X POST http://192.168.4.1/api/headlight-strobe/stop
curl -s  http://192.168.4.1/api/headlight-strobe/stats
```

`stats` 返回（节选）：

```json
{"ok":true,"count":10,"intervalMs":200,"trigger":0,"triggerName":"APP",
 "durationMs":0,"stopMode":0,"maxRunMs":30000,"mode":"COUNT",
 "totalMs":4000,"elapsedMs":1600,
 "supported":true,"stalkVariant":"STALK","active":true,"state":"ACTIVE",
 "flashesDone":3,"flashesTotal":10,"blockReason":"","txOk":6,"txFail":0}
```

### 4.3 持久化

参数存在 NVS 命名空间 `hstrobe`（`count/intervalMs/trigger/durationMs/stopMode/maxRunMs`），掉电保留；
「重置功能设置」不会清这个命名空间。

### 4.4 拦截原因（`blockReason`）

`ALREADY_ACTIVE`（重复触发）/ `STALKLESS_UNSUPPORTED`（无拨杆车型）/ `NO_STOCK_TEMPLATE`（还没收到过真实 0x249）/
`TURN_SIGNAL_ACTIVE`（正在自动打灯）/ `SOURCE_MISMATCH`（触发源和配置不符）/ `SEND_FAILED`（连续 5 次发失败）/
`CAN_EPOCH_CHANGED`（总线恢复/重启）/ `USER_STOP` / `COMPLETE`

## 8. 追加：Web「前爆闪开关」+ 按住拨杆爆闪

### 8.1 行为定义

| 条件 | 行为 |
|---|---|
| 开关 **开** + 向后拉住远光拨杆（0x249 高灯位 = PULL） | 立即开始连续爆闪（PULL/IDLE 交替，间隔 = `intervalMs`） |
| 松开拨杆（连续 3 帧不再是 PULL） | **立即停止**，并补发一帧 IDLE，回到近光 |
| 开关 **关** | 拉杆不再触发；若正在爆闪，立刻停止并恢复 |
| 按住超过 `maxRunMs`（默认 30 s） | 安全兜底，强制停止并恢复 |
| 按住期间 500 ms 收不到 0x249 | 认为总线异常，停止并恢复 |
| 正在自动打转向灯 / 无拨杆车型 / 没有真实 0x249 模板 | 不启动（`blockReason` 说明原因） |

### 8.2 判断依据与防抖

- **信号来源**：本机发出的 0x249 不会被自己接收（TWAI 正常模式），所以 `rx249` 只随整车 SCCM 的 0x249 递增，`realRaw249[1]` 的 bit5:4 就是**物理拨杆的真实状态** —— 不存在“自己触发自己”的反馈环。
- **起爆**：单帧 PULL 即可，但要求该帧 `cksumSelfTest == true`（0x249 校验通过），兼顾零延迟与抗坏帧。
- **松开**：连续 3 帧非 PULL（≈75 ms @40 Hz）才判定松开，避免单帧抖动造成忽停忽闪。
- **最短运行 150 ms**：防止拨杆只发一帧 PULL 时闪一下就断。
- **恢复目标**：按住模式结束时恢复到 **IDLE**（松手后拨杆本来就在 IDLE），不是触发前的 PULL，避免“松手后远光仍亮”。

### 8.5 验证场景

**A. 台架（CAN 分析仪 + 模拟 SCCM）**

1. 开关关：注入 `0x249`，byte1 bit5:4 = 1 → **不应有任何 0x249 注入**；
2. 开关开：注入一帧 PULL → 应在 ~1 帧内出现第一帧注入的 PULL；
3. 持续注入 PULL（40 Hz）→ 抓到的 0x249 应每 `intervalMs` 交替一次，`stats.flashesDone` 持续增长；
4. 停止注入 PULL（改发 IDLE）→ 3 帧内停止，并看到最后一帧 IDLE；
5. 按住中把开关关掉 → 立即停止并回 IDLE；
6. 按住超过 `maxRunMs` → 自动停止，`blockReason=COMPLETE`；
7. 无拨杆车型 / 未收到过真实 0x249 → 不启动，`blockReason` 为 `STALKLESS_UNSUPPORTED` / `NO_STOCK_TEMPLATE`。

**B. 实车（驻车、无人、远离对向车辆）**

1. 打开开关，向后拉住拨杆并保持 → 远光持续快速闪烁；

**C. 回归**

2. 自动转向灯、ALC、NAG、R79 等功能不受影响（爆闪未激活时 `headlightStrobeTick` 仅做一次比较就返回）。

## 10. 追加：按住 2.5 秒才触发 + App 打包

### 10.1 触发条件变更

原来「看到一帧 PULL 就起爆」改为 **连续按住满 `holdDelayMs`（默认 2500 ms）才起爆**：

- 以收到的 0x249 帧为准计时，第一帧 PULL（校验通过）记 `holdPullSinceMs`；
- 任意一帧非 PULL 立即清零计时，**松手不会触发**；
- 空闲超过 500 ms 没有 0x249 也清零，避免断流后误判；
- 起爆后行为不变：松开 → 连续 3 帧非 PULL 停止并恢复 IDLE；`maxRunMs` 兜底。

`holdDelayMs` 已做成参数（0–10000，默认 2500），NVS 键 `holdDelay`，接口：
`POST /api/headlight-strobe/config?holdDelayMs=2500`。

## 11. 事故修复：两路 CAN 无数据 = 板型宏用反了

**现象**：刷入爆闪包后 BODY / CHASSIS 完全收不到帧（收 0、发 0），PARTY 正常。

**真实基准**：用户备份的 `原厂app-0x10000.bin`（v3.29.3，Arduino-ESP32 3.3.12）里，
引脚表为 `(21,23,27,20,22,26)` = **BODY 20/21、CHASSIS 22/23、PARTY 26/27（标准接线）**。

**错误原因**：先前用「官方 C5C6 刷机包」的 C6 镜像当基准做字符串比对，那版是 **X179 扩展板**
（BODY 4/5、CHASSIS 2/3）；而 `P4CAN_BOARD_X179` 只改 4 个整数常量，**不产生任何字符串**，
所以字符串比对看不出差异。于是把 X179 当成正确板型，编出的包让 BODY/CHASSIS 落到未接线的 GPIO2-5，
PARTY（两种板型都是 26/27）不受影响 —— 与现象完全吻合。

| 板型 | BODY | CHASSIS | PARTY |
|---|---|---|---|
| 标准接线（用户的板子，正确） | 20/21 | 22/23 | 26/27 |
| X179 扩展板 | 4/5 | 2/3 | 26/27 |

**判定方法（可复用）**：在 app 镜像里搜 6 个小端 32 位整数
`(BODY_RX, CHASSIS_RX, PARTY_RX, BODY_TX, CHASSIS_TX, PARTY_TX)`，
标准为 `(21,23,27,20,22,26)`，X179 为 `(5,3,27,4,2,26)`。

**加固**：`/api/system/stats` 新增 `canHarness`（"默认 (20-23)" / "X179 (2/3,4/5)"）与 `canPins`，
App「设置 → 诊断 → 系统」直接显示，刷完先核对再上车。

**产物**：`~/Downloads/P4CAN-固件/` 下只保留
`刷这个-爆闪-标准板.ino.bin` / `.merged.bin`（标准接线）与 `回滚-你的原厂app.ino.bin`，
其余（含两个引脚不对的包）全部移到 `旧版本-勿用/`。

> 教训：板型/引脚类差异不会出现在字符串里，**必须校验二进制里的常量表**，不能只比字符串。

## 12. 后雾灯爆闪（0x273 注入）

**控制路径**（依据 Tesla Model 3/Y 车身 DBC）：

| 帧 | 信号 | 位置 |
|---|---|---|
| `0x273` UI_vehicleControl | `UI_rearFogSwitch` | byte2 bit7（mask 0x80） |
| `0x3E3` VCRIGHT_lightStatus | `VCRIGHT_rearFogLightStatus` | byte1 bit1:0（整车回读） |

**做法**：在 RX 路径挂 `rearFogStrobeObserve()`，收到整车 0x273 就缓存模板；爆闪期间每收到一帧立刻回发一份
「只翻转后雾灯位」的副本（与 0x293 变道注入相同的时序策略，避免与整车同 ID 报文抢占）。停止注入后，
整车下一帧就把灯带回它自己的状态，因此不需要额外的恢复逻辑；`stop` 时仍补发一帧原始状态让恢复更即时。

**状态机**（`rear_fog_strobe.h`）：
- `start`：已在运行 → false（HTTP 409 ALREADY_ACTIVE）；模板超过 2 s 未更新 → false（NO_FRAME）；
- 运行中：`rearFogStrobeTick()` 每 `headlightStrobeConfig.intervalMs`（默认 100 ms）翻一次相位，
  `>= 30000 ms` 自动 `stop(TIMEOUT)`；整车 0x273 断流 500 ms 自动 `stop(NO_FRAME)`；
- `stop`：清 active、补发一帧原始状态；`stopReason` 供界面显示。

**集成点**：`vehicle_logic.h`（include）、`can_runtime.h`（CanA/CanB 的 0x273 观察 + tick）、
`web_api.h`（3 个接口）、`dashboard_source.html`（Lighting 面板）+ `tools/build_dashboard.py` 重新生成 `index_html.h`。

**接口**：`GET /api/rear-fog-strobe/stats`、`POST /api/rear-fog-strobe/{start,stop}`。

**产物**：`~/Downloads/P4CAN-固件/刷这个-前大灯+后雾灯爆闪.ino.bin`（标准接线 20-23，1.40 MB）。
