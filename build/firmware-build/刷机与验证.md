## 3. 刷写

### A. OTA（推荐，设备装车时不用拆）

1. 手机连 P4-CAN 热点；
2. App → 设置 → OTA → 选择 `P4CAN-v3.29.3-strobe.ino.bin`；
   （或网页 `http://192.168.4.1` → OTA 页上传同一个文件）
3. 进度到 100% 后设备自动重启，约 15–25 秒重新出现热点。

> App 的 OTA 页会校验：只接受 `.bin`、拒绝 `.merged.bin`、限制 8 MB —— 1.33 MB 的 `.ino.bin` 正常通过。

### B. USB（设备能拿到手时）

```bash
esptool.py --chip esp32p4 -p /dev/cu.usbmodem* -b 921600 \
  write_flash 0x0 ~/Downloads/P4CAN-v3.29.3-strobe.merged.bin
```

## 4. 刷后验证

### 4.1 接口是否在（30 秒）

```bash
curl -s http://192.168.4.1/api/headlight-strobe/config
```

期望：

```json
{"ok":true,"count":10,"intervalMs":200,"trigger":0,"triggerName":"APP",
 "supported":true,"stalkVariant":"STALK","active":false,"state":"IDLE",...}
```

`supported:false` → 车型是无拨杆（Highland stalkless），爆闪不可用，属预期。

### 4.2 App 侧

打开「功能 → 前大灯爆闪」，页面应能读到配置（不再提示“固件没有提供爆闪接口”）。

### 4.3 台架（不接车）

```bash
curl -X POST "http://192.168.4.1/api/headlight-strobe/trigger"
curl -s  "http://192.168.4.1/api/headlight-strobe/stats"   # flashesDone 递增
curl -X POST "http://192.168.4.1/api/headlight-strobe/stop"
```

### 4.4 实车（驻车、无人、远离对向车辆）

1. `supported` 为 `true` 且不是 `NO_STOCK_TEMPLATE`（说明已收到真实 0x249 模板）；
2. 触发 10 次 / 200 ms：目视 10 次远近切换，总时长约 4 秒，结束回到触发前状态；
3. 远光常开时触发：结束仍回到远光常开；
4. 触发中打转向灯：物理转向正常，爆闪结束后转向继续；
5. 触发中按「停止并恢复」：立即回到触发前状态。

## 5. 回滚

OTA 上传 `P4CAN-v3.29.3-stock-rollback.ino.bin` 即可恢复原版（同一套编译参数，功能等价于出厂的 v3.29.3）。

## 6. 风险提示

1. **ChipVariant 必须匹配**：本次按 `postv3`（P4 v3.0+）编译。若设备是 P4 v1.x，镜像会在启动阶段被 IDF 拒绝，**表现为设备一直不出热点**，只能 USB 重刷 prev3 版。不确定时优先走 USB 刷写，出问题 2 分钟可恢复。
2. **OTA 失败无法联网**：如果新固件崩溃重启循环，`192.168.4.1` 不会出现，只能拆下来 USB 救。
3. **爆闪期间 0x249 被独占**：注入式转向灯/ALC/one-shot 会暂停约 `count × 2 × interval`（默认 4 秒），物理拨杆不受影响。
4. **远光爆闪可能眩目**，只在封闭场地/驻车环境验证。
