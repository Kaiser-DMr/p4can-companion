# v3.35.3 中文固件：EAP / TLSSC 免重启最小移植

参考仓库：`baicyber/P4can-No-Reboot`（tag `v3.29.3-nr3`，commit `9c3b653`）
目标仓库：`06066060606060/P4can-universal-unlock`（本地中文基线 `v3.35.3-zh`）

## 1. 参考版本改了什么

参考仓库把修复放在独立头文件：

- `source/firmware/P4can-unlock-more/feifan_eap_norestart.h`

核心逻辑：

1. 车端发 `0x331` 时，除原来的“读-改-重发”外，把**补丁后的载荷**缓存到 RAM；
2. 每个上电周期最多写一次 NVS（避免逐帧擦写 flash）；
3. CAN B（chassis）就绪后开 **60 s 窗口**，以 **10 Hz** 补发缓存帧，最多 **600 帧**；
4. 车自己开始发 `0x331`（2 s 内有新鲜帧）立即停手，回到读-改-重发；
5. 只在“被封车辆 + TLSSC 恢复”都开启时动作，发送走 TX 屏障、管理员挂起、USB 被动与 epoch 检查；
6. `ESP_ERR_TIMEOUT`（屏障被爆闪/AP/维护占用）单列为“让位”，不计失败，下周期重试。

参考接入点：

- `can_runtime.h`：CAN B `case 0x331` → `feifanEapNrObserve331(f)`；service 段 → `feifanEapNrTick()`
- `.ino`：启动时 `feifanEapNrLoad()`
- `feifan_api.h`：`/api/...` 开关与 `status.eapNr` 字段
- `dashboard_source.html`：开关与状态行

## 2. 目标版本的结构差异

| 参考（v3.29.3） | 目标（v3.35.3-zh） | 处理 |
|---|---|---|
| `bannedCar` + `tlsscRestoreEnabled` 两个条件 | `bannedCar` 已移除，只剩 `chinaRestoreEnabled` | 条件改为 `chinaRestoreEnabled`；开启恢复帧即视为“被封车辆”场景 |
| `doInjectTlsscRestore(f)` | `service_settings.h: chinaRestoreEcho(...)` | 在两条 0x331 路径旁增加观察，不替换原函数 |
| `canTxTwaiTransmit(&out, epoch)`（默认 BOTH fresh mask） | `p4CanSendFrame(&out)` + 显式 `canTxBarrierMutex`，支持 YL 的 CHASSIS=extra | 用目标现有门控：取屏障锁、检查 epoch/管理员挂起/USB 被动/`p4CanAllRunning` |
| 仅 `activeCanBIsChassis()`（非 YL） | CHASSIS 在 YL 上是 extra，不在 CAN B | 直接按 `P4_CHASSIS` 发送，兼容 YL |
| `twai_message_t` 观察 | CAN B 是 `twai_message_t`，extra 是 `CanFrame` | 两个 `eapNrObserve331` 重载 |
| `feifan_api.h` + 网页 UI | 中文网页结构不同，不改 UI | 只把 `eapNr` 统计并入 `/api/service-mode/stats`，并加 `POST /api/service-mode/eapnr?enabled=` |

## 4. 冲突与处理

| 冲突 | 处理 |
|---|---|
| 与爆闪 / AP / Lighting 抢 TX 屏障 | `xSemaphoreTake(...,0)` 失败记 `replayBusy`，不推进 10 Hz 节流、不计失败，下周期重试 |
| 与 `chinaRestoreEcho` 同时发 0x331 | 车端 0x331 新鲜 2 s 内补发让位；最多重叠 2 s，之后只走原读-改-重发 |
| YL 的 CHASSIS 在 extra 总线 | 固定 `out.bus=P4_CHASSIS`，不用 `p4CanSendB()`；门控用 `P4_CHASSIS != p4CanBusB()` 判断是否需要 summon admission |
| NVS 冲突 | 独立命名空间 `eapnr`，不碰 `features` / `hstrobe` / `p4gpio` |
| 缓存帧过期 | 每个上电周期第一次成功观察后写一次；后续帧只更新 RAM；下次上电用最新已持久化帧 |
| 旧版 `bannedCar` 不存在 | 只以 `chinaRestoreEnabled` 为前提；未开启恢复帧时绝不发 0x331 |

## 7. 烧录与验证

1. OTA/串口刷入后确认 `fwVersion = v3.35.3-strobe1-eapnr1-zh`
2. 进 Service Mode 开启「中国市场恢复帧」；App 的 EAP 开关应显示开启
3. 看 `/api/service-mode/stats` 的 `eapNr`：
   - `enabled=true`、`prereq=true`
   - `cacheValid=true`、`cacheHex` 以 `1B` 开头（byte0 低 6 位为 SELF_DRIVING）
   - `stockRx` 增长；`burst` 增长到 ≤600；`replayOk` 增长；`replayFail` 应为 0
   - 车端开始发 0x331 后 `burst` 停止增长
4. 断电重启车辆：车机不应再需要人工重启才能出现 TLSSC
5. 爆闪/灯光测试同时触发：`replayBusy` 可增长，但 `replayFail` 不应增长，CAN 无 bus-off
6. 关闭恢复帧：`prereq=false`，不再补发；重新打开：`burst` 从 0 重新开始
7. 中文页面、爆闪、GPIO、OTA 功能回归

## 8. 风险与限制

- **官方 v3.35.6 源码未公开**，本移植落在可编译的 `v3.35.3-zh` 上；不能直接改 3.35.6 二进制。
  官方 3.35.6 的 `restoreForce` 已提供“按间隔重发最后 0x331”，可能缓解同一问题，但启动窗口/NVS 缓存语义不同，需实测。
- 若车机在 P4-CAN 上线**之前**就完成 DAS 配置读取，软件无法补救，仍需人工重启一次；这是总线时序限制。
- 补发窗口 60 s、10 Hz、最多 600 帧；按 500 kbit/s、8 字节帧估算，额外负载约 0.2–0.3%。
- NVS 每轮上电最多写一次，flash 寿命影响可忽略；但缓存帧是“本轮第一次看到的 0x331”，若车辆配置在行驶中变化，下次上电可能先补发旧帧，直到收到新帧。
- 未做实车回归：以上验证清单需在驻车/台架完成。
