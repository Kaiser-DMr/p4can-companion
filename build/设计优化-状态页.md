# P4-CAN「状态」页 · 信息展示优化方案（v2.0 设计稿）

> 设计流程按 Figma 工作流执行：定画布/断点 → 定 Design Token → 定基础组件 → 组屏 → 交互与状态 → 交付标注。
> 本仓库同时给出**可直接导入 Figma 的 token 文件** `design-tokens.json`，以及**已按此稿实现的原生界面**（SwiftUI），截图见 `screenshots/design-*.png`。

---

## 1. 设计目标

| 目标 | 落地方式 |
|---|---|
| 一眼看到「设备在不在、车在不在跑」 | 顶部 Hero 卡统一承载设备身份 + 连接态 + 三枚健康胶囊 |
| 关键数值前置、次要信息后置 | 挡位 / AP / NOA / 扭矩做成 2×2 KPI 四宫格，紧跟 Hero |
| 三路 CAN 可比较、可诊断 | 每路一行「状态 + 收发 + 成功率进度条 + 帧龄」，底部加接收帧占比条 |
| 趋势可读 | 扭矩卡先给「当前 / 峰值 / 均值」三指标，再给曲线（含均值虚线） |
| 全站一致 | 颜色、字号、圆角、间距全部收敛到 token；组件只保留 1 套 |

**不改数据口径**：所有值仍来自 `snapshot` / `profile/status` / `features/status` 等固件接口；设备没上报就显示「—」或「读取中…」，不猜默认值（v1.8 规则继续生效）。

## 2. Design Token

### 2.1 颜色（语义色，自动适配深色/高对比）

| Token | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `bg/canvas` | 页面底色 | `systemGroupedBackground` | 近黑 |
| `bg/card` | 卡片 | `secondarySystemGroupedBackground` | 深灰 |
| `bg/tile` | 卡内瓦片 / 进度槽 | `tertiarySystemGroupedBackground` | 更深一档 |
| `text/primary` | 主文字 | label | label |
| `text/secondary` | 说明、单位 | secondaryLabel | secondaryLabel |
| `state/ok` | 在线、正常 | systemGreen | systemGreen |
| `state/warn` | 注意、拒帧 | systemOrange | systemOrange |
| `state/err` | 离线、Bus-Off | systemRed | systemRed |
| `state/info` | 强调、图表主色 | systemBlue | systemBlue |
| `chart/c1..c3` | 三路总线分类色 | blue / teal / indigo | 同色（提高 10% 亮度） |

> 规则：颜色只做**辅助**，任何状态都必须同时有图标或文字（色盲友好）。

### 2.2 字体

| Token | 规格 | 用途 |
|---|---|---|
| `font/display` | 26pt / Semibold / Rounded / 等宽数字 | KPI 大数字 |
| `font/title` | `.title2.bold` | Hero 标题（车型） |
| `font/section` | `.subheadline.semibold` | 卡片标题 |
| `font/body` | `.subheadline` | 控件标题 |
| `font/value` | `.caption.monospaced` | 计数、字节、毫秒 |
| `font/caption` | `.caption2` | 脚注、单位、时间 |

正文全部使用 Dynamic Type 语义字号；只有「大数字」用固定字号 + Rounded + `monospacedDigit()`，保证刷新时不跳动。

### 2.3 间距与圆角（8pt 网格）

| Token | 值 | 用途 |
|---|---|---|
| `space/1` | 8 | 卡内元素间距 |
| `space/1.5` | 12 | 行内块间距 |
| `space/2` | 16 | 卡片内边距、卡片间距、页面左右边距 |
| `radius/card` | 16 | 卡片 |
| `radius/tile` | 12 | KPI 瓦片、图标底 |
| `radius/chip` | 999 | 胶囊标签 |

### 2.4 阴影 / 层级

不使用投影。层级靠 **背景色差（canvas → card → tile）** 表达，符合 iOS 分组列表语义，也避免深色模式下阴影失效。

## 3. 信息架构：调整前后

| 层级 | 调整前（v1.8） | 调整后（v2.0） |
|---|---|---|
| 1 | 连接卡（"已连接 / 已同步"） | **Hero 卡**：车型 + 拓扑 + 固件 + 连接胶囊 + 3 枚健康胶囊 + 同步时间 |
| 2 | 快捷开关 | **KPI 四宫格**：挡位 / AP / NOA / 扭矩（大数字 + 脚注） |
| 3 | 车辆实时（7 条键值行） | **快捷开关**（图标 + 标题 + 副标题 + 开关） |
| 4 | 扭矩趋势 | **CAN 总线**：状态、收发、成功率、帧龄、占比条 |
| 5 | CAN 总线 | **扭矩趋势**：当前/峰值/均值 + 曲线 + 均值虚线 |
| 6 | 车型与能力 | **车型与能力**：车型 + 拓扑胶囊 + 三路角色 + 2 列能力标签 |
| 7 | 蓝牙 / OTA / 设备 / 实时活动 | 蓝牙 / OTA / 设备 / 实时活动（保持次要，顺序不变） |

关键变化：**把"车辆实时"的 7 行键值拆成 4 个 KPI 瓦片**（挡位、AP、NOA、扭矩），其余低频字段留在「全部数据」里，不再占用首页纵向空间。

## 5. 关键区块规格

### 5.1 Hero 卡
- 左侧 3pt 竖条：连接态色（在线绿 / 连接中橙 / 离线红）
- 标题：车型名（`profileName`），无数据时回退 `P4-CAN`
- 副标题：拓扑 + 固件版本（最多 2 行）
- 右上：连接胶囊（图标 + 文案）
- 第二行：`CAN 3/3`、`蓝牙 开`、`LAB 开` 三枚胶囊，均带图标
- 分隔线 + 底行：`已同步 · HH:mm:ss`（左）、`每 1.5 秒自动同步`（右）

### 5.2 KPI 四宫格
2 列等宽，间距 8；每格：图标 + 标签（caption）、数值（26pt Rounded）、脚注（caption2）。
无数据时数值显示 `—`（灰色），不回落 0。

### 5.3 CAN 总线
- 卡头：`n/3 在线` 胶囊 + `canBusCount = n`
- 每路：
  - 行 1：状态圆点 + `CAN 1 · BODY` + 右对齐状态胶囊（RUNNING 用 ✓）
  - 行 2：三列等宽计数 `收 / 发 / 拒`（拒 > 0 用橙色）+ 右侧帧龄
  - 行 3：发送成功率进度条（语义色）+ 百分比
- 卡尾：`接收帧占比` 分段条 + 图例（CAN 1 51% 等），数据为 0 时整块隐藏

### 5.4 扭矩趋势
- 指标行：当前 / 峰值 / 均值（各带 N·m 单位）
- 曲线：面积渐变 + 折线 + **均值虚线**；Y 轴靠左、3 个刻度；X 轴 3 个刻度
- 采样不足 2 点时显示「等待 NAG 扭矩数据…」，不画空图

### 5.5 车型与能力
- 车型标题 + 拓扑胶囊
- 三枚角色胶囊：`CAN A / BODY`、`CAN B / CHASSIS`、`PARTY / PARTY`
- 能力标签 2 列网格：图标 + 名称 + ✓/—/?，未知不复用「不支持」样式

## 6. 交互与状态

| 状态 | 表现 |
|---|---|
| 加载中 | 卡片骨架（redacted），不显示 0 / 关 |
| 设备未上报字段 | `—`（大数字）或「读取中…」（开关行） |
| 命令执行中 | 控件禁用，`isBusy` 生效 |
| 命令成功 | 底部 Toast（绿）+ 轻触觉 |
| 命令失败 | 底部 Toast（红）+ 错误触觉，文案为固件原文 |
| 写成功但回读未变 | Toast 提示「设备未回读该状态」 |

## 7. 无障碍与适配

- 所有图标 `accessibilityHidden`，容器合并朗读（"CAN 1 · BODY，RUNNING，收 128934 帧，成功率 99%"）
- 状态不依赖颜色：圆点 + 文字胶囊 + 图标三重表达
- 支持 Dynamic Type 到 XXXL：KPI 数字 `minimumScaleFactor(0.7)`，标题最多 2 行
- 支持深色模式（截图 `design-03-dark.png`）、iPhone 各尺寸；Mac Catalyst 下自动切换为侧边栏布局
- 触控目标 ≥ 44×44（开关与按钮）

## 8. 主要调整点（一句话版）

1. **合并「连接 + 设备信息 + 三路健康」为一张 Hero 卡**，首屏第一眼就能判断设备与车辆状态。
2. **把 7 行键值表拆成 2×2 KPI 瓦片**（挡位 / AP / NOA / 扭矩），信息密度更高、扫读更快。
3. **CAN 总线改成"每路一卡行"**：状态胶囊 + 收发计数 + 成功率进度条 + 帧龄，并新增**接收帧占比条**，三路可横向对比。
4. **趋势卡增加当前 / 峰值 / 均值三指标与均值虚线**，从"只有一条曲线"变成"可判断的数值"。
5. **新增统一组件**：`MetricTile`、`StatusChip`、`SlimProgress`、`RatioBar`，并把功能列表的支持徽章也换成 `StatusChip`，全站视觉一致。
6. **颜色/字号/圆角/间距全部收敛为 token**，同时输出 `design-tokens.json`，可直接在 Figma 建 Variables。
7. **保留 v1.8 的数据真实性规则**：无数据一律 `—` / 「读取中…」，不出现默认开关或默认数值。

## 8.1 导航简化（v2.0）

移除了状态页顶部的三个工具图标（全部数据 / 立即同步 / 连接引导）——它们在系统页已有等价入口，
首屏只保留居中的「设备状态」标题，减少顶部视觉噪音：

| 原入口 | 现入口 |
|---|---|
| 全部数据 | 系统 → 数据浏览；CAN 卡底部「查看全部总线字段」 |
| 立即同步 | 下拉刷新（另有 1.5 秒自动轮询） |
| 连接引导 | 系统 → 连接 → 查看连接引导（离线首屏也有按钮） |
