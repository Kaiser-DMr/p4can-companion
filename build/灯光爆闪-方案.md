# 「灯光爆闪」可行性方案

> 结论先说：**转向灯爆闪可以做，工作量不大；大灯/远光爆闪要额外逆向，风险高。**
> 依据：`06066060606060/P4can-universal-unlock` 源码（v3.29.3 对应分支）

## 1. 固件现有的能力（决定了可行性）

`vehicle_logic.h` 里已有完整的转向灯注入链路：

| 项 | 现状 |
|---|---|
| 报文 | `SCCM_turnIndicatorStalkStatus`，**0x249**，DLC 4，**CAN B / VH CAN** |
| 发送函数 | `sendStalkFrameCanB(turn, txEpoch, directUser)` |
| 载荷来源 | **用车上真实 0x249 帧做模板**，只改 rolling counter + turn nibble，再重算 CRC；抓不到模板会 `BLOCKED`，不会瞎发 |
| 校验 | `leftStalkChecksum(frame, counter)`（与车型共用模型） |
| 权限 | `directUser = true` 时绕过 ULC 免确认抑制 |
| 统计 | `blinkerTxRecordLocked(...)` 已有 TX 成功/失败/来源记录 |

也就是说：**"按一下转向灯"这件事固件已经会做，爆闪只是"按很多下"**。

## 2. 两条路线

### A. 转向灯 / 双闪爆闪（推荐）

- 新增一个 strobe 状态机：以 `hz` 频率在 `LEFT ↔ IDLE`（或 `LEFT ↔ RIGHT`）之间切换，持续 `durationMs`；
- 每次切换调 `sendStalkFrameCanB(...)`，天然复用模板/计数器/CRC；
- 频率建议 **2–8 Hz**：0x249 本身是 40Hz 级报文，车身按"拨杆按下/松开"解析，太快会被丢弃或识别成连续拨动；
- 固件改动量约 **80–150 行**（FSM + 两个 HTTP 处理器 + 状态 JSON 几个字段）。

### B. 大灯 / 远光爆闪（不推荐先做）

- 仓库里**没有**前照灯/远光的编码：已解码的只有 `0x249` 拨杆、`0x334` 动力、`0x3F8` 驾驶辅助、`0x239` 车道模型、`0x3C2 / 0x102` 车身开关等；
- 需要先用固件自带的「CAN 研究捕获 RAW」录一段真实开/关远光，反推 ID 与 bit，再写编码器；
- 风险：车身控制器（VCFRONT）对灯光报文有校验与超时监控，乱发可能落 DTC，且大灯继电器/驱动不接受高频开关。

## 3. 建议的接口契约（与现有风格一致，全 query 参数）

```
POST /api/lights/strobe?enabled=1&hz=4&durationMs=5000&pattern=alternate
     enabled      0/1
     hz           1..8        频率
     durationMs   200..30000  持续时间；enabled=0 时立即停
     pattern      alternate | left | right

GET  /api/lights/strobe
     { "supported": true, "active": true, "pattern": "alternate",
       "hz": 4, "remainingMs": 3200, "txOk": 24, "txFail": 0,
       "blocked": false, "blockReason": "NO_STOCK_TEMPLATE" }
```

安全约束（固件内做）：
- 任何时刻只允许一个 strobe；`enabled=0` 立即停并回 `IDLE`；
- `NO_STOCK_TEMPLATE` / `CAN_B_NOT_RUNNING` 时拒绝启动并在状态里给出原因；
- 建议上限 8Hz、30s，超时自动停，避免误触后一直闪。

## 4. App 侧改动（我这边）

新增模块 `light.strobe`（`section: .body`，图标 `light.beacon.max`）：

| 控件 | 类型 | 参数 |
|---|---|---|
| 启动爆闪 | toggle | `enabled` |
| 频率 | slider | `hz` 1–8，步长 1 |
| 持续时间 | slider | `durationMs` 500–10000，步长 500 |
| 模式 | select | `alternate` 左右交替 / `left` 仅左 / `right` 仅右 |

实时状态读 `active / remainingMs / txOk / txFail / blocked`；`blocked` 时在页面顶部显示原因（例如"尚未捕获 0x249 模板"）。

按现有机制，只要固件端点存在，页面会自动出现；不存在时控件显示「读取中…」而不是假开关（v1.8 的规则）。

## 5. 必须说明的限制

1. **法规**：道路上使用爆闪（尤其红蓝/白色高频闪）在绝大多数地区违法，仅限封闭场地/展演；App 内会加显式警告与二次确认。
2. **硬件**：转向灯是 LED + BCM 驱动，高频开关会增加驱动与继电器压力；8Hz 已接近"电子闪光器"上限。
3. **语义**：0x249 是"拨杆"报文，不是"灯"报文。爆闪在车看来等于快速反复拨杆，极端情况下可能被判定为故障或触发双闪逻辑。
4. **依赖模板**：必须先在路上正常打一次转向灯让盒子抓到真实 0x249，否则固件会拒绝注入（这是保护，不是 bug）。

## 6. 工作量估算

| 部分 | 内容 | 量级 |
